# Decisions

Why the stack is what it is, so nobody (human or agent) re-litigates it by accident. Changing one of these is
fine — but do it deliberately, update this file, and migrate the whole app rather than mixing approaches.

| Area              | Choice                                                                  | Why                                                                                                                                                                                                                                                                          | Revisit if…                                                                                   |
| ----------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Framework         | **Expo** (React Native, New Architecture)                               | React Native team's recommended framework; one TypeScript codebase for iOS + Android with truly native UI; huge ecosystem; agents know it well; first-class native escape hatches (config plugins, Swift/Kotlin modules).                                                    | You need a game engine or heavy 3D (use a game engine instead).                               |
| Native projects   | **CNG** — `ios/`/`android/` generated, git-ignored                      | Upgrades are `npx expo install expo@next` instead of hand-merging Xcode/Gradle projects; native config is declarative and reviewable.                                                                                                                                        | An SDK needs edits no config plugin can express.                                              |
| Routing           | **Expo Router** + native stack + **NativeTabs**                         | File-based, typed routes, deep links for free; real platform navigation (Liquid Glass tab bar on iOS 26, Material 3 on Android).                                                                                                                                             | —                                                                                             |
| Styling           | **StyleSheet + tokens + `makeStyles`**                                  | Zero dependencies and build magic, never breaks on SDK upgrades, fastest possible at runtime, and every agent writes it fluently.                                                                                                                                            | You strongly prefer Tailwind classes → NativeWind or Uniwind (one or the other, everywhere).  |
| Server state      | **TanStack Query**                                                      | Caching, retries, refetch-on-focus, mutations, offline-friendly; industry default.                                                                                                                                                                                           | —                                                                                             |
| Client state      | **zustand**                                                             | Tiny, hook-based, no providers, trivial persistence.                                                                                                                                                                                                                         | —                                                                                             |
| Validation        | **zod 4**                                                               | Runtime validation of API responses, env and stored JSON with inferred TS types.                                                                                                                                                                                             | —                                                                                             |
| Local storage     | **expo-sqlite kv-store** (sync)                                         | Works in Expo Go, synchronous (no loading flicker), and the same package gives a full SQLite DB later.                                                                                                                                                                       | Profiling shows KV is hot → `react-native-mmkv` (needs a dev build).                          |
| Unit/component    | **Jest + jest-expo + RNTL 14**                                          | Expo's supported setup; RNTL tests behave like users and ship agent docs in `node_modules`.                                                                                                                                                                                  | —                                                                                             |
| E2E               | **Maestro**                                                             | YAML flows that are easy for humans and agents to read/write; no native test code; works on simulators and EAS.                                                                                                                                                              | You need deep native assertions → Detox.                                                      |
| Lint/format       | **ESLint (eslint-config-expo + react-hooks compiler rules) + Prettier** | Expo-supported config, React Compiler rules, guardrails for the design system; Prettier keeps diffs clean. **ESLint stays on v9** (the version `npx expo install` picks): on v10, `eslint-plugin-react` inside eslint-config-expo crashes (`getFilename is not a function`). | A future eslint-config-expo supports ESLint 10 — then upgrade with `npx expo install eslint`. |
| Package manager   | **npm**                                                                 | Zero setup, default everywhere (EAS, CI), fewest surprises.                                                                                                                                                                                                                  | Install speed matters a lot → bun.                                                            |
| Build & delivery  | **EAS** Build / Submit / Update / Workflows                             | Cloud builds without Xcode, managed signing credentials, one-command store submission, OTA updates, CI-like workflows.                                                                                                                                                       | Org mandates self-hosted CI → `eas build --local` or Fastlane.                                |
| OTA compatibility | **`runtimeVersion.policy: fingerprint`**                                | Automatically prevents shipping JS to an incompatible native build.                                                                                                                                                                                                          | —                                                                                             |
| Variants          | **`APP_VARIANT` in `app.config.ts`**                                    | Dev, preview and production install side by side with distinct names/IDs.                                                                                                                                                                                                    | —                                                                                             |
| Platforms         | **iOS + Android only**                                                  | Focus; fewer platform branches.                                                                                                                                                                                                                                              | You want a web version → add `react-dom` + `react-native-web`.                                |
| Repo shape        | **One app per repo** (copied from the base)                             | Simple for humans and agents; each app evolves and upgrades independently.                                                                                                                                                                                                   | Several apps share lots of code → monorepo with shared packages.                              |
